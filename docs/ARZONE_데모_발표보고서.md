# ARZONE CUBE — 스마트폰·Quest 3 AR 데모 발표 보고서

> 특수 에디션 AR 앨범 CUBE · 한이음 드림업
> 담당: AR 개발 파트

---

## 1. 한 줄 요약

**스마트폰에서 AR 기능을 먼저 완성하고, 같은 구조를 그대로 Meta Quest 3로 확장했다.**
두 기기 모두 "인식/호출 → 스틱맨 소환 → 실제 공간 위 걷기"가 동작한다.

---

## 2. 개발 목표

| 항목 | 내용 |
|---|---|
| 1차 목표 | 스마트폰에서 동작하는 AR 프로토타입 |
| 2차 목표 | 동일 구조를 Quest 3로 확장 (재작업 최소화) |
| 데모 범위 | 인식 → 캐릭터 소환 → 실제 공간 위 걷기 |
| 데모 캐릭터 | 스틱맨(졸라맨) — 코드로 생성한 임시 에셋 |

> 실제 앨범 캐릭터·아바타는 이후 단계. 데모는 **동작 구조 검증**이 목적이다.

---

## 3. 스마트폰 데모

**흐름:** 피규어 정면 인식 → 스틱맨 소환 → 더블탭으로 걷기

| 단계 | 기술 | 설명 |
|---|---|---|
| 인식 | Vuforia Image Target | 물체(피규어)의 정면을 이미지로 인식. **1회 인식** |
| 소환 | 코드 생성 스틱맨 | 인식 지점에 캐릭터 생성 |
| 이동 | 더블탭 → 평면 위 이동 | 화면을 두 번 터치한 지점으로 걸어감 |

**핵심 판단**
- 정면 2D 이미지 인식 = Vuforia 무료 범위 (연속 추적·Model Target은 유료)
- "한 번 인식 후 호출" 구조라 무거운 추적이 불필요

---

## 4. Quest 3 데모

**흐름:** 패스스루 화면에서 손/컨트롤러로 스틱맨 소환 → 실제 바닥·책상 위를 걸음

| 단계 | 기술 | 설명 |
|---|---|---|
| 화면 | Passthrough | 헤드셋 카메라로 실제 방을 보며 AR 오버레이 |
| 입력 | 핸드 트래킹(핀치) + 컨트롤러 | 손 핀치 또는 컨트롤러 트리거로 소환·이동 |
| 포인팅 | 레이 + 레티클 | 가리키는 지점을 시각적으로 표시 |
| 공간 인식 | MRUK | 스캔한 실제 바닥·책상 표면 위에 캐릭터를 세우고 이동 |

**핵심 판단**
- Quest는 **인식 불필요.** 인식은 폰에서 1회로 끝나고, Quest는 소환·상호작용만 담당
- MRUK로 실제 공간 표면을 인식해 캐릭터가 바닥·책상 위를 자연스럽게 이동

---

## 5. 폰 → Quest 확장에서 재사용한 것

| 구분 | 재사용 | 플랫폼별 교체 |
|---|---|---|
| 캐릭터 생성·걷기 로직 | ✅ 코드 그대로 공유 | — |
| 입력 처리 | 인터페이스로 분리 | 폰=터치 / Quest=손·컨트롤러 |
| 공간 배치 | 인터페이스로 분리 | 폰=이미지 평면 / Quest=MRUK 표면 |
| 렌더링·머티리얼 | ✅ 공용(URP) | — |

> 캐릭터·걷기 코드는 **양쪽 프로젝트가 동일 파일을 공유**한다. 플랫폼 차이는 입력·공간 부분만 갈아 끼운다.

## 6. 현재 상태

**완료**

- Quest 3: 소환 → 실제 표면 위 걷기 동작 (패스스루·핸드트래킹·컨트롤러·포인터)
