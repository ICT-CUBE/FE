## 7. 거래 생성(POST /trades)용 '거래 안 걸린 판매 상품'이 시드에 없습니다

> 구매 확정 쪽은 08-25 시드 개편(거래 1 = DELIVERED)으로 해결됐습니다. 남은 건 거래 생성입니다.
> (12번의 셀프 거래 대안은 "판매 3종 데모 후 진행" 답변으로 물 건너감 — 시드 추가가 유일한 길입니다.)

```
POST /users/me/trades (sellListingId 1·2·3 전부)
→ 409 TRADE_ALREADY_EXISTS "이미 거래가 생성된 판매 상품입니다."
```

앱은 결제하기에 거래 생성을 배선해 뒀습니다(08-28) — 성공해야 완료 모달이 뜨므로,
시드가 없으면 데모에서 결제가 항상 실패 토스트로 끝납니다.

**여쭤볼 것: 거래가 안 걸린 판매 상품(sellListing) 하나를 시드에 추가해 주실 수 있나요?**

## 13. 음성(VOICE) 세션 메시지 전송 — 명세와 서버가 다릅니다. 지금 동작을 유지해 주세요 (2026-08-28)

명세서 상세("대화 메시지 응답" 처리 정책)에는

> 음성 대화 세션으로 메시지 전송을 요청하면 404: CONVERSATION_SESSION_NOT_FOUND를 반환한다.

라고 돼 있는데, **실서버는 201로 정상 처리합니다** (직접 확인: VOICE 세션 생성 → 메시지 전송 201
→ 아바타 답변 수신. 시험 세션은 삭제해 뒀습니다).

**앱은 이 동작에 의존합니다** — 음성 대화 화면에서 주제를 고르면 VOICE 세션으로 메시지를 보내
아바타 답변을 화면에 띄웁니다(STT 가 없어 이 방식이 유일한 응답 경로). 세션 종료 시 GPT 제목도
붙어서 음성 대화 목록이 자연스럽게 채워집니다.

**여쭤볼 것: 명세대로 404 로 막지 마시고, 지금처럼 VOICE 세션도 메시지 전송을 허용해 주실 수
있나요?** (가능하면 명세서 쪽을 갱신해 주세요. 막아야 한다면 미리 알려주세요 — 앱 흐름을 바꿔야 합니다.)

## 14. ★ 시드 사용자 1의 로그인 정보가 필요합니다 (2026-08-30, 급함)

auth 배포 확인했고 앱에 로그인·회원가입을 붙였습니다(가입→토큰 저장→전 요청 Bearer 부착).
그런데 **데모 시드(큐브 1·갤러리·대화·거래 1 등)는 전부 사용자 1의 것**입니다.
새로 가입한 계정은 큐브 소유권이 없어 홈부터 `CUBE_OWNERSHIP_NOT_FOUND` 가 납니다
(직접 확인: 가입한 테스트 계정 id 11 — 정리해 주셔도 됩니다).

**여쭤볼 것: 사용자 1로 로그인할 수 있는 이메일·비밀번호를 알려주시거나 시드에 넣어주실 수
있나요?** 이것 없이는 데모에서 시드 데이터를 하나도 못 봅니다.

참고: 명세서엔 토큰 기한 3일인데 실제 응답은 `expiresIn` 1년입니다 — 데모엔 오히려 좋아서
그대로 두셔도 됩니다. 확인만 부탁드립니다.

## 15. 스테이지 미디어 파일 포맷 문제 — 썸네일 전부 + 영상 2개 (2026-08-30)

### 15-1. 영상 2개가 사실은 MP3 입니다

```
…/stage_music_video/mv_handlebars.mp4    → 실제 내용: MP3 (ID3v2.4 헤더)
…/stage_music_video/mv_seoul city.mp4    → 실제 내용: MP3 (ID3v2.4 헤더)
```

확장자만 .mp4 이고 내용물이 음원이라 앱에서 Handlebars·Seoul City 뮤비가 재생되지 않습니다.
**진짜 영상 파일로 교체 부탁드립니다.** (나머지 뮤비·콘서트 영상은 전부 정상 MP4(H.264,
moov 선두)로 확인했습니다 — 스트리밍 잘 됩니다.)

### 15-2. 썸네일이 AVIF 입니다 — JPEG/PNG 로 다시 올려주세요

`GET /stages` 연동 후 썸네일이 전부 안 뜹니다. 확인해 보니 **확장자만 .jpg 이고 실제 포맷은
AVIF** 입니다 (파일 헤더 `ftyp avif` 확인):

```
…/stage/music_video_thumbnail/mv_extral.jpg      → ISO Media, AVIF Image
…/stage/music_video_thumbnail/mv_handlebars.jpg  → ISO Media, AVIF Image
…/stage/concert_video_thumbnail/concert_*.jpg    → 전부 동일
```

Unity(폰 앱)는 JPEG/PNG 만 디코딩할 수 있어서 AVIF 는 "Data Processing Error" 로 전부
실패합니다. 갤러리·예절샷 이미지들은 진짜 JPEG 라 잘 뜹니다 — 스테이지 썸네일만 문제입니다.

**여쭤볼 것: 스테이지 썸네일(뮤비·콘서트 전부)을 진짜 JPEG 또는 PNG 로 다시 올려주실 수
있나요?** (파일명·URL 은 그대로 두고 내용물만 바꿔주시면 앱은 수정 없이 바로 뜹니다)

## 16. 음성 대화 TTS API 요청 (2026-08-30)

음성 대화 흐름을 이렇게 나누기로 했습니다(유저 확정):
- **말→텍스트(STT)**: 프론트가 안드로이드 내장 음성 인식으로 변환해 기존 대화 API(`POST …/messages`)로 보냅니다 — 앱 구현 완료.
- **답변 텍스트→음성(TTS)**: **백엔드가 변환해서 프론트에 넘겨주기로** 한 부분입니다.

**여쭤볼 것: 아바타 답변을 음성으로 받는 API 를 만들어주실 수 있나요?**
예: `POST /api/v1/tts` (body: `{ "text": "..." }` → 응답: 오디오 파일(mp3) 또는 오디오 URL),
또는 메시지 응답에 `audioUrl` 필드를 추가해 주셔도 됩니다. 형태는 편하신 쪽으로 정해주시면 맞추겠습니다.

## 17. 구매 확정이 500 을 냅니다 (2026-08-31)

```
GET   /users/me/trades/1          → 200 (타임라인 5단계 정상)
PATCH /users/me/trades/1/complete → 500 INTERNAL_SERVER_ERROR
```

auth 개편 이후 실기에서 재현됩니다. 짚이는 것:
- 이 거래를 예전에 이미 확정했었다면 **재확정 시 409(TRADE_NOT_DELIVERED 등)가 아니라 500** 이
  나는 것일 수 있습니다 — 그렇다면 상태 검증 쪽 예외 처리 확인 부탁드립니다.
- 아니면 auth 개편으로 사용자↔거래 연결 로직에서 터지는 것일 수도 있습니다.

**여쭤볼 것: 서버 로그에서 이 500 의 원인을 확인해 주실 수 있나요?**
(데모 시연을 위해 거래 1을 다시 DELIVERED 로 되돌려 주시면 더 좋습니다.)
