# ARZONE — 프론트엔드 주요 결정사항

> 왜 그렇게 만들었는지의 기록. 각 항목 = 결정 · 근거 · 기각한 대안.

## 1. 범위·전략

### D1. 시안 우선 원칙 (2026-08-21, 대전제)
화면·UX는 디자인 시안대로 완성하는 것을 최우선으로 한다. 서버 규칙과 시안이 충돌하면
시안이 이긴다(로그에는 진실을 남김). 데모 동선에 없는 경로에 방어 코드를 쌓지 않는다.

### D2. 시안 실측주의
눈대중 금지. Figma export(SVG/3x PNG)를 도구로 실측해 숫자로 맞추고 숫자로 대조 보고.
폰트 크기는 잉크 bbox 역산(글자가 path로 구워져 크기 정보가 없음).

## 2. 아키텍처

### D3. 콜백/코루틴, async 미도입
코드베이스에 async가 0줄 — 씬 전환 중 응답이 파괴된 오브젝트를 건드리는 사고·취소 토큰 배관 비용,
그리고 팀 학습 곡선을 근거로 기각. UnityWebRequest 코루틴과 콜백 관례(ICommunitySource)로 통일.

### D4. ApiClient 단일 창구 + 도메인 인터페이스(+Mock)
"단일 정적 클라이언트만" 안은 Mock 자리가 없어 기각, "인터페이스만" 안은 전송 코드 복붙 위험으로 기각
— 둘을 합침. 첫 슬라이스는 갤러리 3종(읽기 위주·화면 기완성·이미지 로딩/페이징 표준 수립)으로 검증 후 확산.

### D5. DTO ↔ 앱 모델 분리, JsonUtility 유지
Newtonsoft 도입 대신 JsonUtility + enum string 수신·수동 변환. 의존성 최소화.

### D6. 뒤로가기 = 고정 부모 맵 (2026-08-31)
히스토리 스택은 순환 진입 시 무한 루프 유발 — 화면마다 정해진 부모로 가는 BackMap(55항목)으로 교체.
사진 상세류만 "어디서 왔는지 1단계 기억" 예외.

### D7. 미디어 소유권을 화면 밖으로
AudioSource가 화면에 붙어 있으면 화면 OFF 시 재생이 끊긴다 → MusicPlayer(DontDestroyOnLoad).
VideoPlayer도 상시 호스트 공유 — 상세/전체화면/AR이 같은 재생 상태를 이어받음.

### D8. 스트리밍 = 로컬 즉시 + 서버 교체
서버 URL 대기 없이 로컬로 즉시 재생 시작, 도착하면 같은 위치로 무봉 교체, 실패는 로컬 유지.
데모 네트워크 불확실성 대비.

## 3. 인식(실물 인증)

### D9. Vuforia 유지 + 자체 검증 계층 (2026-08-31)
인식 엔진 전면 자체 개발(ML 분류기) 검토 — 합성 데이터 파이프라인(Blender 렌더→학습→ONNX/Sentis)까지
구축했으나, Vuforia+자체 검증이 실기에서 요구 수준을 충족해 **Vuforia 채택, ML은 보험으로 보존**.

### D10. 위조 판별은 기하+픽셀 이중 검증
- 사진: 시차에 따른 포즈 불안정(거리 널뜀)으로 차단 — "빛 반사 분석"은 신뢰 구현이 어려워 기하로 대체.
- 다리 잘림: 기하로 구분 불가(정품만큼 안정 추적됨 — 실측 결론, Vuforia는 가림=정상 설계) →
  판정 순간 화면 캡처로 다리 구역 픽셀 검증. 판정은 평균이 아닌 **최대값**(다리는 가늘어 샘플 일부가
  배경에 떨어지는 게 정상).
- 시차 요구(옆으로 움직이기)는 UX 부담으로 **제거**(유저 결정) — 사진 방어는 위 두 축이 담당.

### D11. 측정 좌표계 교정 (실측으로 확정한 2건)
① Vuforia 월드가 카메라 고정·대상 이동 → 절대좌표 측정은 폰을 움직이는 행위 자체를 "흔들림"으로
오판 → 대상 로컬 상대좌표로 전환. ② 월드 1유닛=1cm(이동 253~1385"cm"·8cm가 화면 1px 붕괴로 검증)
→ 미터 정규화 상수. ③ 튜닝값은 씬 직렬화가 코드 기본값을 덮는 사고를 겪어 **전부 const**로.

### D12. 인식 UX
가짜 진행바(연출) 폐기 → 실제 인식 상태 반영(추적 시 차오름). 단, **하강 금지**(유저: 떨어지면 짜침).
실루엣 가이드는 내장 오버레이(추적 시 강제 숨김·크기 고정 불가) 대신 텍스처만 받아 프레임 안에
인식 종료까지 상시 표시. 크기 출렁임은 1회 스냅샷으로 고정.

## 4. 아바타

### D13. 정적 포즈 시스템 (애니메이션 에셋 없이)
프로젝트에 .anim이 전무 — 휴머노이드 본 FromToRotation으로 화면별 정적 포즈 (리그 축 부호를 몰라도
되는 방식). 프레이밍은 뼈 기반 자동 — 모델 교체(4만→189만)에도 구도 유지.

### D14. 고폴리곤(189만) 채택
실측(Adreno 840): 홈/AR 전 구간 30fps 고정, 소환 1회 ~0.5s 로드 — 채택. 단서: 플래그십 기준,
중급기 미보증. 스킨 바운드는 매프레임 재계산(블렌더 export 바운드 협소 → 컬링 소실 방지).

### D15. 표정 = VRM Expression 최소 세트
앱이 쓰는 표정은 aa(립싱크)·blink(깜빡임) 2개 — 셰이프키도 2개만 제작(비용 최소화).
바인딩 오류(happy에 묶임)는 VRM 바이너리 직접 수정으로 교정.

### D16. 립싱크 = RMS 볼륨 방식
음소 분석 대신 오디오 음량으로 입 개폐 + 가사 줄 게이트(간주에 입 다뭄) — 데모 품질 충분, 구현 위험 최소.

## 5. 대화·음성

### D17. STT 프론트, TTS 백엔드
서버에 STT가 없어 Android 내장 인식기(JNI 직접, 플러그인 무의존). TTS는 서버 audioUrl 재생.

### D18. 인식기 재사용 구조
매 발화마다 destroy/create → 서비스 연결이 끊겨 다음 발화가 오류(5/11)로 튕김(삼성 실기) →
**인스턴스 재사용(cancel→start)** + 늦은 콜백 세대(gen) 차단 + 일시 오류 0.6s 자동 재시도 2회(무토스트).

### D19. 낙관적 전송
내 말풍선 즉시 표시 → 실패 시 회수+토스트. 세션 종료는 화면 이탈 훅(GPT 제목 자동 생성 활용).

## 6. UX 세부 (실기에서 확정)

| 결정 | 근거 |
|---|---|
| 전송 버튼 PointerDown 처리 | 키보드 닫힘→버튼 이동→클릭 취소되는 실기 버그 |
| 입력 필드 인라인 편집 + 보라 캐럿 | Android TMP 기본값은 커서 이동·한 글자 삭제 불가 |
| 런타임 생성 필드 재초기화 | TMP는 OnEnable 시점에 textComponent 없으면 캐럿을 영영 안 만듦 |
| 키보드 리프트 실측 방식 | TouchScreenKeyboard.area 기기 편차 → decorView 가시영역, 15%~60% 범위 필터 |
| 401 전역 → 로그인 이동 | 만료 토큰 방치 시 화면마다 오류 도배 |
| 커뮤니티 표시 시점 프로필 조회 | 저장 시점 스냅샷은 프로필 변경이 옛 글에 반영 안 됨 |
| 유리 = 정점색 + 부분 발광 테두리 | Unity UI에 backdrop-blur 부재, Linear/sRGB 차이로 시안 합성색을 α1로 |
| 탭바 등 오버레이 규약 | Sheet/Modal은 화면 미등록 — 스와이프 내리기/여백 탭 닫기 통일 |
