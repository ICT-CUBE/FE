# ARZONE 트러블슈팅 모음

> 증상 → 원인과 교훈. 실기에서 실제로 겪은 것만.

## 텍스트 대화 입력

* 사진을 붙이면 입력창이 키보드 밑으로 내려가고 전송 아이콘만 따로 놀았다.
→ 좌표를 정하는 함수가 둘이었다. `LayoutBar`(높이 반영·리프트 무시) 와 `ApplyLift`(리프트 반영·높이 무시) 가 번갈아 덮어썼다. 위치 계산은 한 함수로 합쳐야 한다.
* 앵커를 바꾸었더니 입력창이 통째로 사라지고 눌리지도 않았다.
→ 코드 기본값만 `838.5→54.5` 로 고치고 씬의 `838.5` 를 안 고쳤다. `[SerializeField]` 는 씬 값이 이긴다 — 좌표계를 바꾸면 씬 값도 같이 바꾸어야 한다.
* 한글을 치는 동안 입력창에 `</u>` 같은 태그 글자가 그대로 떴다.
→ TMP 입력창은 한글 조합 중인 글자에 `<u>…</u>` 태그로 밑줄을 친다. 그런데 텍스트 컴포넌트를 `richText = false` 로 꺼두어서 태그 문자가 노출됐다. 입력창은 richText 를 끄면 안 된다 — 조합형 IME 가 리치텍스트를 전제로 동작한다. 태그 주입이 걱정되면 전송 시점에 이스케이프한다.

## 텍스트 대화 화면

* 아바타 말풍선만 이름보다 20px 오른쪽에 있었다.
→ 말풍선 행의 부모(root)는 화면 412 가 아니라 372(좌우 여백 20 안쪽)인데, 좌표 상수는 시안의 화면 기준값이었다. 게다가 말풍선 x 는 **두 곳에서 설정**돼서(생성 직후 + 이름 줄 붙일 때) 한 곳만 고치면 다른 곳이 덮어쓴다. 좌표를 넣기 전에 부모가 어느 좌표계인지부터 확인하고, 같은 값은 같은 변수로 묶는다.
* 아바타 말풍선의 시각이 "오후 3:4" 에서 잘렸다.
→ 자르는 건 화면 끝(412)이 아니라 **스크롤 뷰포트 마스크(392)** 였다. 넘침 한도는 화면이 아니라 마스크 기준으로 계산해야 한다.
* 새 대화를 누르면 "대화 세션을 찾을 수 없다"가 떴다.
→ 서버가 **메시지 0개인 세션의 상세 조회를 404** 로 돌려준다(실측). 새 대화 직후엔 상세 조회를 생략하는 걸로 우회. 서버 엣지케이스는 추측 말고 curl 로 재현부터.
* 대화 목록의 새 대화들이 전부 무제목으로 남았다.
→ GPT 제목은 **세션 종료 PATCH 를 불러야** 생성된다(첫 메시지 2개 기반). 화면을 떠날 때 종료를 안 부르니 영영 무제목이었다. 스펙 설명을 끝까지 읽을 것 — "상태 저장"이 사실 "종료+제목 생성"이었다.
* 보관(북마크) 버튼이 아무 반응이 없었다.
→ `onClick` 이 `null` 이었다. 시안에 있는 버튼을 만들 때 배선까지 됐는지 전수 확인할 것.
* 검색해도 실제 대화가 안 나왔다 / 최근 검색에 칩이 안 쌓였다.
→ 검색 대상이 하드코딩 더미 6줄이었고, 검색어를 recent 에 추가하는 코드 자체가 없었다. "동작하는 것처럼 보이는 더미"가 제일 위험하다 — 데이터 출처를 확인할 것.

## 아바타 (VRM)

* 아바타가 T포즈로 서 있었다.
→ 프로젝트에 애니메이션 에셋이 0개다. 옛 아바타는 스키닝 없는 '조각상'이라 티가 안 났을 뿐. 리깅된 모델은 포즈를 잡아줄 코드(관절별 FromToRotation)나 애니메이션이 반드시 필요하다.
* 포즈 디렉터가 있는데도 T포즈 + 카메라가 발 앞까지 들어갔다.
→ `GetComponentInChildren(includeInactive: true)` 가 **꺼둔 옛 아바타**를 먼저 잡아, 포즈는 숨은 아바타에 걸리고 카메라도 거길 따라갔다. 활성 + `isHuman` 으로 걸러야 한다. 로그의 "키 0.20" 한 줄이 결정적 단서였다 — 진단 로그를 아끼지 말 것.
* AR 소환하니 아바타가 거대했다 / 프레이밍이 발만 크게 잡았다.
→ 막 생성된 SkinnedMeshRenderer 의 `bounds` 는 갱신 타이밍에 따라 발치 조각만 준다. 키 실측·카메라 프레이밍은 **휴머노이드 본 위치**로 계산해야 한다(생성 직후에도 정확).
* 옷이 좌우 반쪽만 흰색이었다.
→ VRoid 는 검정 옷을 "흰 텍스처 × 검정 baseColorFactor"로 만드는데, **shadeColorFactor 엔 그 곱이 빠진 채** 밝은 색으로 저장돼 있었다. MToon 은 그늘을 shadeColor 로 칠하니 조명 반대쪽이 통째로 하얘진다. VRM 재질의 shade 에 같은 곱을 적용해 해결. "반쪽만 이상하다" = 조명·셰이딩부터 의심.
* 아바타 화면에서 아예 안 보였다.
→ 3D 뷰용 RawImage 자리(AvatarSurface)가 **알파 0** 자리표시자였다. 빈 placeholder 에 뭔가 꽂을 땐 알파도 같이 확인(이 함정으로만 4번째).
* 아바타가 홀쭉했다.
→ 정사각(824²) RenderTexture 를 세로로 긴 rect 에 그대로 스트레치했다. RawImage 는 비율 유지가 없다 — `uvRect` 로 rect 비율만큼 크롭해야 한다.
* 아바타가 무대 원판 위에 떠 있었다.
→ 바운드 중심을 화면 중앙에 놓는 프레이밍이라 발 위치가 임의였다. "발이 프레임 어디에 오는가"(발 앵커)로 계산 기준을 바꿔야 바닥에 선다.
* 손이 그로테스크하게 말렸다.
→ FromToRotation 은 손끝 방향만 잡고 **손바닥이 어딜 보는지는 방치**다. 손바닥 법선은 본 위치로 역산 가능 — cross(중지 방향, 검지→새끼)는 손의 카이랄리티상 항상 한쪽이 손바닥이다.

## UI 일반

* 탭바 발광 링이 모서리 호 4개만 남았다.
→ 링 추출(MakeRing)이 "투명 픽셀로부터의 거리"로 테두리를 찾는데, 이 알약 텍스처는 도형이 캔버스를 꽉 채워 투명 픽셀이 모서리 구석뿐이었다. 캔버스 밖도 투명으로 간주하는 시드를 추가해 해결. 알고리즘의 전제(경계 존재)를 에셋이 만족하는지 확인할 것.
* 진행바에 빛번짐이 남았다.
→ 216장 시퀀스에 알파 40~110 글로우가 깔려 있었고, 같은 시퀀스가 **두 벌**(Resources/ProgressBar + Sprites/ProgressSequence) 있어서 한 벌만 고치면 안 고쳐진 것처럼 보였다. 같은 에셋이 복제돼 있는지 전수 검색부터.
* 스캔 화면 우측 상단 버튼이 흰 덩어리 + □□□ 글자였다.
→ 유니티 기본 버튼(Create→Button) 그대로였다 — 기본 흰 판(UISprite) + 기본 영문 폰트(LiberationSans, 한글 없음). 어두운 목업 배경에선 안 보이다가 카메라가 깔리자 드러났다. 코드로 만든 TMP·기본 생성 UI 는 폰트/스프라이트를 반드시 프로젝트 것으로 교체.
* 친밀도 획득 토스트의 아이콘이 깨졌다.
→ 문구의 ✨ 이모지 — Pretendard 에 이모지 글리프가 없다. 토스트·라벨에 이모지 금지(홈 말풍선 🖤 는 같은 이유로 이미지로 따로 얹은 전례).
* 미션 바로가기가 무반응이었다.
→ 이동 로직은 있는데 대상 화면(goScreen)을 채우는 곳이 없었다. 제목 키워드→화면 매핑으로 해결.
* 알림 "모두 읽음" 버튼이 안 보였다.
→ 어두운 알약(#0F1115) 위 보라 글자였다. 시안은 보라 **테두리** 알약 — 높이가 딱 맞는 전용 스트로크 에셋(bg_pill_stroke 39×37)이 이미 있었다.
* 프로필 아이콘이 화면마다 달랐다.
→ 홈·허브·마켓의 유저 프로필이 토끼 그림으로 하드코딩. 선택값(ProfileStore) 연동 컴포넌트로 통일. 단 커뮤니티 글쓴이·마켓 판매자는 '남의 프로필'이라 통일 대상이 아니다.

## API 연동

* 주문 상세가 조용히 씬 목값으로 돌고 있었다.
→ 서버 시드가 개편되며 기본 tradeId(3)가 삭제됐다. 시드는 언제든 바뀐다 — 연동 후에도 주기적으로 서버를 다시 찔러볼 것.
* 서버 음원으로 바꾸자 클립이 죽었다(스트리밍 전환 때 예방).
→ streamAudio 클립은 다운로드 핸들러의 압축 데이터를 재생 중 디코드한다 — **요청을 Dispose 하면 클립이 죽는다.** 캐시가 요청째 보관해야 한다.
* 세션 종료 PATCH 가 400.
→ multipart 전용 엔드포인트인데 Unity 의 MultipartFormDataSection 은 빈 값을 거부한다. 본문을 손으로 조립해 빈 값 파트를 보내면 서버(FastAPI)가 null 로 읽는다(실측 204).

## 뷰포리아

* 유니티 에디터가 "No editor configuration file available" 에러를 반복했다.
→ 데이터셋의 dat/xml 만 복사해서다. MTG 의 unitypackage 에는 에디터용 authoringinfo.xml 이 따로 들어 있다 — **unitypackage 로 임포트**해야 한다.
* 모델 크기가 실물과 12배 차이났다.
→ Tripo AI 내보내기는 실물 크기와 무관하게 ~1m 로 정규화된다. 실물 실측(8cm)으로 UnitScaleFactor 를 패치. 단 **Blender 를 거치면 크기를 노드 스케일로 보존**하므로 유닛까지 또 패치하면 이중 적용된다 — 최종 크기는 항상 "좌표×노드스케일×유닛"으로 재검증.

## 공통 교훈

* "없다/안 된다"는 보고는 절반이 틀렸다 — grep 전수, 서버는 curl 재현, 에셋은 픽셀 실측으로 직접 확인한다.
* 같은 값이 두 곳에서 설정되면 반드시 한 곳이 덮어쓴다 — 위치·색·상태는 소유자를 하나로.
* 진단 로그 한 줄(좌표·크기·개수)이 스크린샷 열 장보다 빠르다.
